# Quartus Project

The `quartus/` directory contains the Intel Quartus Prime project and build configuration required to synthesize, fit, and program the FPGA implementation.

The repository is intentionally structured so that the HDL source code remains independent of the Quartus project.

The reusable RTL implementation is stored in `rtl/`, while simulation and verification sources are stored in `tb/` (TestBench).

The `quartus/` directory therefore contains only FPGA project metadata, device configuration, pin assignments, timing constraints, and other Quartus-specific build files.

A typical repository structure is:

```text
fpga-hft-nn/
├── build/
├── config/
├── data/
├── python/
├── rtl/
│   └── ...
├── tb/
│   └── ...
└── quartus/
    ├── ...
    └── README.md
```

This organization avoids treating Quartus-generated files as the source of the FPGA design.

Instead, the HDL sources in `rtl/` and `tb/` remain reusable by simulation tools, alternative FPGA projects, and automated build flows.

The Quartus project references these external source directories rather than maintaining duplicate copies of the HDL files.


## FPGA Target

The initial FPGA target is the **Terasic Cyclone V GX Starter Kit (C5G)**.

The Quartus project targets the following Cyclone V GX device:

```text
5CGXFC5C6F27C7
```

This provides a concrete hardware platform for synthesis, timing analysis, resource-utilization analysis, and eventual hardware validation of the neural-network inference architecture.


## Board Interfaces

The initial project uses a minimal set of board-level resources required for FPGA bring-up and verification.

The relevant C5G connections are:

| Function | Board Resource | FPGA Pin | Purpose |
| --- | --- | --- | --- |
| System clock | 50 MHz clock | `PIN_R20` | FPGA design clock |
| User input | `KEY0` | `PIN_P11` | Manual control/reset input |
| User output | `LEDG0` | `PIN_L7` | Basic status/debug indication |

Additional board interfaces can be added to the Quartus assignments as the FPGA implementation evolves.


## Transceiver Limitation

The Cyclone V GX device provides high-speed serial transceivers, but the C5G platform does not provide transceiver capability sufficient to terminate **10GbE or 25GbE directly**.

The available board transceiver interfaces operate at up to approximately **3.125 Gb/s**.

Consequently, a future 10GbE or 25GbE system architecture must place the corresponding high-speed Ethernet interface behind an **external PHY, bridge, or other suitable interface device** rather than connecting a 10GbE/25GbE SerDes interface directly to this FPGA.

Conceptually:

```text
10GbE / 25GbE
      |
      v
+----------------+
| External PHY / |
|     Bridge     |
+----------------+
      |
      v
+----------------+
| Cyclone V GX   |
|                |
| FPGA inference |
| pipeline       |
+----------------+
```

The initial Quartus project therefore focuses on implementing and validating the deterministic neural-network inference pipeline independently of the final high-speed Ethernet physical interface.


## Project Reproducibility

The `quartus/` directory should contain the files necessary to recreate the FPGA project without committing the complete set of files generated by Quartus during compilation.

In particular, project configuration, device selection, source-file references, pin assignments, and timing constraints should remain under version control.

Generated compilation databases, temporary files, reports, programming intermediates, and other reproducible build artifacts should remain outside version control where appropriate.

This keeps the repository focused on the files that define the design rather than on files that Quartus can regenerate.
